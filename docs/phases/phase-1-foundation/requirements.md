# Phase 1 需求文档

## 1. 阶段名称

基础后台与核心内容模块上线

## 2. 阶段目标

本阶段目标是把当前后台从“工程骨架”建设为“最小可用后台”，让团队可以开始在后台录入和管理核心业务内容。

本阶段不追求完整业务闭环，而是优先搭建基础能力和主数据录入能力。

## 3. 背景

当前前端 Demo 已经明确了主要业务对象：

- 资讯
- 活动
- Builder
- 联系入口

但这些数据仍主要由前端本地静态数据维护，后台与后端还未正式承接。

因此，Phase 1 的任务是建立后台基础设施和核心录入模块。

## 4. 用户与角色

### 4.1 Admin

可完成全部管理动作。

### 4.2 Editor

可管理内容、活动和 Builder，但不负责系统级配置。

## 5. 需求范围

### 5.1 登录能力

系统需要提供后台登录能力，至少支持：

- 管理员登录
- 登录态保持
- 未登录跳转登录页

### 5.2 资讯管理

后台需要支持资讯内容的基础 CRUD：

- 创建文章
- 编辑文章
- 删除文章
- 查看文章列表

字段建议至少包含：

- 标题
- slug
- 摘要
- 分类
- 标签
- 受众
- 封面图
- 正文
- 来源名称
- 来源链接
- 是否精选
- 状态

### 5.3 活动管理

后台需要支持活动基础 CRUD：

- 创建活动
- 编辑活动
- 删除活动
- 查看活动列表

字段建议至少包含：

- 标题
- slug
- 时间
- 地点
- 城市
- 类型
- 状态
- 摘要
- 封面图
- 活动详情

### 5.4 Builder 管理

后台需要支持 Builder 基础 CRUD：

- 创建 Builder
- 编辑 Builder
- 删除 Builder
- 查看 Builder 列表

字段建议至少包含：

- 姓名
- slug
- 头衔
- 城市
- 角色
- 简介
- 故事
- 能力标签
- 关注方向
- 合作方式
- 可联系状态
- 是否 featured
- 封面图

### 5.5 媒体上传

后台需要支持图片与基础资源上传：

- 上传文件
- 返回可用 URL
- 在文章、活动、Builder 中引用

### 5.6 基础 API

后端需要提供上述模块对应 API，供后台和后续前台接入使用。

## 6. 非目标

本阶段明确不做：

- Leads 完整闭环
- Contact 表单入库
- 活动报名入库
- Builder 合作入库
- 知识库
- AI Agent Skill
- 复杂权限系统
- 高级统计报表

## 7. 核心业务流程

### 7.1 发资讯

1. 管理员或编辑登录后台
2. 进入资讯管理页
3. 创建文章并填写内容
4. 上传封面图
5. 保存草稿或发布

### 7.2 发活动

1. 管理员或编辑登录后台
2. 进入活动管理页
3. 创建活动
4. 填写时间地点等信息
5. 保存草稿或发布

### 7.3 上架 Builder

1. 管理员或编辑登录后台
2. 进入 Builder 管理页
3. 创建成员资料
4. 上传头像或封面
5. 保存草稿或发布

## 8. 验收标准

满足以下条件即视为本阶段完成：

1. 后台可登录
2. 可通过后台创建、编辑、删除文章
3. 可通过后台创建、编辑、删除活动
4. 可通过后台创建、编辑、删除 Builder
5. 可上传图片并在上述模块中引用
6. 后端已具备对应 API 能力

## 9. 输出物

本阶段完成后应至少产出：

- 基础后台页面
- 基础后端模块
- 核心数据表
- 媒体上传能力
- Phase 1 设计文档
