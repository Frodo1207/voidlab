# Phase 2 需求文档

## 1. 阶段名称

当前业务闭环跑通

## 2. 阶段目标

本阶段是第一个明确业务里程碑。

目标不是继续扩展后台页面数量，而是把当前网站已有业务真正跑起来，让系统从“可编辑后台”进化到“可运营业务系统”。

## 3. 背景

Phase 1 完成后，系统已经具备：

- 后台登录
- 资讯管理
- 活动管理
- Builder 管理
- 媒体上传

但当前系统仍未完成前台与后台的完整闭环，也没有统一承接对外意向。

因此，Phase 2 必须解决“展示”和“转化”之间的断层。

## 4. 业务目标

本阶段需要打通以下四个闭环：

1. 资讯闭环
2. 活动闭环
3. Builder 闭环
4. Leads 闭环

## 5. 需求范围

### 5.1 前台切换为 API 数据

前台核心模块应逐步从静态数据迁移到 API：

- Insights
- Events
- Builders

要求：

- 列表页读取 API
- 详情页读取 API
- 前台与后台数据保持一致

### 5.2 Contact 表单入库

Contact 页面应提供真实提交能力，提交后自动写入 Leads。

至少应支持：

- 联系人姓名
- 联系方式
- 意向内容
- 来源标记为 Contact

### 5.3 活动报名 / 预约入库

活动页面需要承接用户报名或预约行为，提交后自动生成 Lead。

至少应支持：

- 活动标识
- 用户姓名
- 联系方式
- 报名说明
- 来源标记为 Event

### 5.4 Builder 合作发起入库

Builder 详情页的合作发起动作应真实入库，并进入 Leads。

至少应支持：

- Builder 标识
- 用户姓名
- 联系方式
- 合作诉求
- 来源标记为 Builder

### 5.5 Leads 模块

后台需要新增 Leads 模块，至少支持：

- Leads 列表
- Lead 详情
- Lead 来源识别
- Lead 状态流转
- 跟进备注

状态至少包含：

- `new`
- `contacted`
- `following`
- `converted`
- `invalid`

### 5.6 基础站点配置

为了减少前台继续硬编码，需支持最基础的站点配置项：

- 联系方式配置
- 首页精选位基础配置
- Banner 基础文案配置

## 6. 非目标

本阶段不做：

- 高级数据分析
- 复杂审批流
- AI Skill
- 知识库
- 复杂自动化营销

## 7. 用户与角色

### 7.1 Admin

管理全部模块和全部 Leads。

### 7.2 Editor

管理文章、活动、Builder 和部分站点配置。

### 7.3 Ops / Sales

查看和跟进 Leads。

## 8. 核心业务流程

### 8.1 内容闭环

1. 后台发布文章
2. 前台资讯页展示文章
3. 用户阅读内容

### 8.2 活动闭环

1. 后台发布活动
2. 前台活动页展示
3. 用户报名或预约
4. Leads 自动生成

### 8.3 Builder 闭环

1. 后台上架 Builder
2. 前台展示 Builder
3. 用户发起合作
4. Leads 自动生成

### 8.4 Contact 闭环

1. 用户通过 Contact 页发起联系
2. 系统创建 Lead
3. 运营跟进 Lead

## 9. 里程碑定义

满足以下条件时，视为达成“当前业务可交付”里程碑：

1. 资讯、活动、Builder 前台均由后台数据驱动
2. Contact、Event、Builder 的外部意向都能进入 Leads
3. Leads 可以在后台查看和更新状态
4. 团队可以不改代码完成日常核心运营动作

## 10. 验收标准

1. 后台发出的文章能在前台稳定展示
2. 后台创建的活动能在前台稳定展示
3. 后台创建的 Builder 能在前台稳定展示
4. Contact 表单提交能生成 Lead
5. 活动报名或预约能生成 Lead
6. Builder 合作发起能生成 Lead
7. Leads 可查看、可跟进、可变更状态

## 11. 输出物

本阶段完成后应至少产出：

- 前台 API 化改造
- Leads 模块
- Contact / Event / Builder 提交能力
- Phase 2 设计文档
