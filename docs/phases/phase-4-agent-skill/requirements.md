# Phase 4 需求文档

## 1. 阶段名称

AI Agent 运营 Skill 接入

## 2. 阶段目标

本阶段目标是让 AI Agent 能以受控方式协助团队运营后台，承担重复、结构化、标准化的后台操作。

这个阶段不是做“万能 AI”，而是做“可以安全调用后台标准动作的 Skill”。

## 3. 背景

在 Phase 1-3 完成之前，系统的数据结构、权限边界和运营动作都还不够稳定，不适合直接交给 Agent。

Phase 4 的前提是：

- 后台模块稳定
- API 标准化
- 权限边界清晰
- 关键动作可审计

## 4. 需求范围

### 4.1 Skill 基础能力

需要建设一个可供 AI Agent 调用的 Skill，至少支持：

- 创建文章
- 编辑文章
- 发布文章
- 创建活动
- 编辑活动
- 创建 Builder
- 更新 Builder
- 上传媒体资源
- 查询 Leads
- 更新 Leads 状态

### 4.2 标准动作接口

Skill 所依赖的后台动作必须标准化，要求：

- 输入结构化
- 输出结构化
- 校验明确
- 错误信息明确

### 4.3 权限与审计

Skill 的操作必须满足：

- 有独立鉴权方式
- 有操作日志
- 有失败反馈
- 有受限动作边界

### 4.4 人机协同方式

系统应支持以下协同模式：

- Agent 创建草稿，人审核发布
- Agent 补录结构化信息
- Agent 查询待跟进 Leads
- Agent 辅助整理运营数据

## 5. 非目标

本阶段不做：

- 完全自治式代运营
- 开放式策略决策
- 知识库主功能
- 无边界自然语言改系统配置

## 6. 核心用户

### 6.1 管理员 / 运营者

通过自然语言触发 Skill。

### 6.2 AI Agent

通过 Skill 调用标准能力，执行结构化动作。

## 7. 典型使用场景

### 7.1 上传文章

用户输入文章信息，Skill 调用标准接口创建文章草稿或直接发布。

### 7.2 上传 Builder

用户输入成员资料，Skill 协助写入后台并返回结果。

### 7.3 创建活动

用户输入活动关键信息，Skill 调用接口完成活动创建。

### 7.4 查看 Leads

用户让 Agent 查看最近 Leads，Skill 返回结构化数据。

## 8. 成功标准

1. Agent 可以安全创建文章
2. Agent 可以安全创建活动
3. Agent 可以安全创建或更新 Builder
4. Agent 可以查询 Leads 并更新状态
5. 所有操作都有明确结果和错误反馈

## 9. 输出物

本阶段完成后应至少产出：

- Agent Skill 说明
- 标准动作接口
- 操作审计方案
- Phase 4 设计文档
