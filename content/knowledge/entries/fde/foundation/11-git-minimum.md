## 一句话结论

Git 不只是命令集合，而是把你的工作变成“可追溯工程”的最小工具。

## 这一章要讲什么

- 提交应该怎么写（让别人看得懂，也让未来的你看得懂）
- 分支/回滚/冲突：转行最常用的那部分
- 用 Git 记录“迭代过程”，而不是只存最终结果

## 交付物

- `git-notes.md`
- 一个带 5 次提交历史的小项目

## 验收标准

- 你能用 `git log` 解释：每次提交改了什么、为什么这么改

## 常见坑

- 懒得提交：一口气改一堆，最后没法定位问题
- 只会 `git add . && git commit`，不会回滚和处理冲突
