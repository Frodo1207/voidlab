## 一句话结论

最小闭环不是 demo，而是“能跑、能上线、能复现、能解释”的产品原型。

## 这一章要讲什么

- 什么叫“最小闭环”：从数据到接口到页面到部署都跑通
- 为什么要选一个内容管理类小系统做第一版（CRUD + 登录 + 角色）
- 第一版做到什么程度就够用（不要一开始就做成平台）

## 本阶段项目建议

做一个“内容条目管理”的最小系统：列表、详情、新建、编辑、删除，带登录与简单角色。

## 交付物

- 一个可运行项目仓库
- 一个线上地址
- `README.md`（如何运行、如何部署、常见问题）

## 验收标准

- 你能在新电脑上按 README 复现运行
- 你能说清：数据怎么存、接口怎么走、页面怎么渲染

## 常见坑

- 把“最小闭环”做成只在本地能跑的 demo（没有部署、没有环境变量说明）
- 一上来就做复杂权限/多租户/插件化，结果主链路没跑通
