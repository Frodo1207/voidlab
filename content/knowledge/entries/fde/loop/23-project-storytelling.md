## 一句话结论

转行不是只看你会不会写代码，而是看你能不能解释自己交付过什么、怎么交付的。

## 这一章要讲什么

- 把项目讲清楚的最小结构：需求 → 取舍 → 实现 → 上线 → 复盘
- 简历项目段落怎么写（让面试官能追问下去）
- 3 分钟讲解稿怎么组织（让对方能理解你做了什么）

## 交付物

- 简历项目段落：`resume-snippet.md`
- 3 分钟讲解稿：`pitch-3min.md`
- 复盘：`postmortem.md`

## 验收标准

- 你能讲清：需求 → 取舍 → 实现 → 上线 → 复盘

## 常见坑

- 只描述“用了什么技术”，不描述“解决了什么问题/如何取舍”
- 复盘只写过程，不写结果（指标、问题、下一步改什么）
