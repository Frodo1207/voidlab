## 一句话结论

Agent 宿主不是框架本身，但它决定了你如何观察任务、控制边界和验收交付。对零基础来说，先学会在宿主里“看懂一个任务是怎么发生的”，往往比先学某个框架 API 更重要。

## 这一章要讲什么

- 工作区是什么
- 工具区与结果区怎么看
- 文件产物为什么比聊天记录更重要
- 为什么宿主工具会影响你的 Agent 开发手感

## 为什么这一章要单独讲

很多人第一次接触 Agent 开发，脑子里会自动跳到“选框架”：LangChain、LangGraph、AutoGen、自己手写，或者直接问“是不是要先学 MCP”。但零基础真正先碰到的，不是这些，而是一个更基础的问题：

> 我到底是在什么地方“开发”这个 Agent？

对多数人来说，第一站不是某个代码框架，而是 `Codex`、`Trae` 或其他类似的 Agent 宿主。你在这些宿主里定义任务、选择工作区、让它读写文件、看工具调用、检查结果、决定是否返工。也就是说，**你第一门要学会的不是框架，而是工作台。**

这和上一章讲的“6 个槽位”正好能对上：宿主工具不是替你发明骨架，而是把这套骨架可视化出来，让你能看见任务是怎么跑的。

## Agent 宿主到底是什么

最简单的理解方式是：**Agent 宿主就是一个承载 Agent 运行的工作台。**

它通常会帮你把这些东西组织到一起：

- 任务输入区：你怎么告诉它这次要干什么
- 工作区：它能读写哪些文件
- 工具执行区：它这次调了什么工具
- 结果区：这次到底交付了什么

所以宿主工具最重要的价值，不是“品牌差异”，而是它把原本抽象的 Agent 运行过程，变成一个可以被观察、被控制、被验收的界面。

## 工作区：为什么零基础第一步就要学边界

工作区是宿主里最容易被忽略、但也是最关键的一个概念。因为一旦进入真实任务，Agent 不再只是在聊天框里输出几段文字，而是要读文件、写文件、生成产物、修改目录结构。

工作区回答的是：

- 这次任务允许碰到哪些文件
- 这次任务的产物应该落到哪里
- 这次任务和别的任务怎么隔离

如果你不先学会工作区，后面几乎一定会碰到这些问题：

- 这次任务读到了不该读的旧资料
- 输出文件写进了奇怪目录
- 你根本不知道这次运行改了哪些文件

所以对零基础来说，学会“先设工作区，再开始任务”，几乎等于学会了 Agent 开发里的第一层工程边界。

## 对话区：这里不是闲聊区，而是任务定义区

很多人第一次用宿主工具，会把中间的大对话区继续当成“聊天区”来使用。但在 Agent 开发里，它更应该被理解成：

- 任务定义区
- 约束确认区
- 返工说明区

你在这里说的每一句话，最好都能回到“任务契约”那 5 个部分：

- 目标
- 输入
- 约束
- 输出
- 验收

换句话说，这里不是“想起什么说什么”，而是“定义这次运行该怎么发生”。后面那一章《Prompt 不是咒语，是契约》其实就是在把这个区域的写法讲透。

## 工具区：这里告诉你它到底做了什么

宿主工具最有价值的一点，是它通常不会把 Agent 的动作完全藏起来。你能看到：

- 它什么时候读了文件
- 它什么时候写了产物
- 它有没有调用搜索或外部接口
- 某个动作有没有失败

这对零基础非常重要，因为它第一次把“模型在想什么”这个抽象问题，替换成了更可控的问题：

- 它读了什么
- 它做了什么动作
- 它失败在哪一步

也就是说，工具区是你的“诊断台”。如果没有这一层，你很容易把所有问题都归因于“模型不行”。但有了这一层，你能开始区分：

- 是任务没写清楚
- 还是工具没接对
- 还是输入边界有问题
- 还是它确实执行失败了

## 结果区：为什么文件产物比聊天记录重要

对零基础来说，一个非常重要的认知转变是：

> 在 Agent 开发里，真正重要的不是聊天记录，而是产物。

结果区最值得看的不是“它说得好不好”，而是：

- 有没有生成文件
- 文件落在哪
- 改了哪些内容
- 有没有预览与打开路径

文件产物之所以比聊天记录重要，是因为它们才是：

- 可验收的
- 可复用的
- 可交接的
- 可版本化的

聊天记录当然也有价值，但它更像过程痕迹。真正能让一个 Agent 变成工程对象的，是产物与路径。

## 为什么不同宿主会影响你的开发手感

这一点很容易被低估。很多人以为宿主工具只是“UI 不一样”，但实际上它会深刻影响你的开发方式。因为不同宿主在这些方面差异很大：

- 工作区的边界设计
- 工具调用的可见度
- 结果区的可读性
- 文件与预览的联动方式
- 你返工一轮的成本

所以宿主不是中性的。一个宿主如果：

- 工作区难理解
- 工具调用看不清
- 产物不好找

那你学习 Agent 开发时，就会更容易把“系统问题”误会成“自己不会”。

反过来，如果宿主把工作区、工具区、结果区设计得很清楚，零基础会更快建立“我正在做一个工作系统，而不是在和一个聊天机器人玩对话”的感觉。

## 零基础第一次上手，应该怎么观察一个宿主

你不需要第一次就研究它的全部功能。只要抓住下面这 5 个观察点就够了：

1. 我现在的工作区到底在哪里  
2. 这次任务允许它读什么、写什么  
3. 它这次调用了哪些工具  
4. 产物最后落在哪个文件  
5. 如果我觉得结果不对，我该在哪里返工

只要这 5 件事看得清，宿主对你来说就已经“够用”了。

## 一个最小上手动作

如果你现在要第一次真正感受宿主的工作方式，我建议只做一个很小的动作：

- 在工作区里放一个 `input/notes.md`
- 让 Agent 把它整理成 `output/summary.md`
- 然后观察整个过程：
  - 它有没有真的读到 `input/notes.md`
  - 它有没有把产物写到 `output/summary.md`
  - 结果区里能不能看到产物路径

这个动作很小，但它已经把宿主里最重要的三件事都跑通了：边界、工具、产物。

## 这一章读完后，你应该能做到什么

读完这一章后，你不需要成为某个宿主的高级玩家，但你至少应该能做到：

- 看懂一个任务是在什么工作区里运行
- 看懂工具执行和产物落点
- 把宿主当成“工作台”，而不是单纯的聊天界面

只要这个视角切换完成，后面你再去学 Prompt 契约和工具调用，就不会觉得它们是两套东西，而会知道：它们都在同一张工作台上发生。

## 继续阅读

既然已经把宿主看成工作台，下一步就要把对话区里那些“随口一说”的任务说明，压成真正可复用的任务定义。继续读 `03-prompt-as-contract.md`，会把 Prompt 从玄学写法收束成一份工程契约。

## 验收标准

- 你能在宿主里解释“输入在哪、输出在哪、结果怎么看”
- 你能完成一次最小任务并指出产物路径
- 你能说清楚工作区、对话区、工具区、结果区分别承担什么作用
