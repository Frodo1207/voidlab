## Skill 可以理解成：一段被整理好的做事方法

前面已经讲了 LLM、Agent 和 MCP。顺着这条线继续往下，Skill 可以先理解成：**把一段能力整理好，方便下次继续用。**

很多人第一次听到 Skill，会把它理解成一句很厉害的提示词，或者某个神秘的插件名字。其实都不太对。Skill 更像一份被打包好的“做事说明书”：里面不只是有提示词，还可能带着这件事的目标、步骤、工具、输出格式，甚至边界条件。

比如“写会议纪要”可以是一个 Skill，“整理资料并输出摘要”也可以是一个 Skill。“生成旅游路线规划页面”同样可以被整理成一个 Skill。重点不在名字，而在于这段能力是不是已经被收拾得足够清楚，别人拿来就能用，过两天自己也还能继续用。

## Skill 和 Prompt 的区别

Prompt 更像一句临时说的话。

比如临时说一句：“帮我把这份会议记录整理成摘要。”这当然也能做事，但它更像一次性沟通。换一个人、换一批材料、换一种输出格式，往往又得重新解释一遍。

Skill 则更像把这件事固定下来。它会把“输入是什么、步骤怎么走、用哪些工具、最后长什么样”一起整理进来。这样一来，这段能力就不再只是当场说完的一句话，而是变成一块能复用的模块。

简单说：

- Prompt：更像一次性的表达
- Skill：更像整理好的能力包

## Skill 里面通常会放什么

一个 Skill 里，常见会放这几类东西：

- 目标：这段能力到底解决什么问题
- 提示：大脑该怎么理解这类任务
- 工具：需要调用哪些工具，哪些不要乱用
- 步骤：先做什么，后做什么，碰到例外怎么处理
- 输出：最后交付成什么样，写成一段话、一个文件，还是一个页面

所以 Skill 的重点不是“听起来厉不厉害”，而是它有没有把一段能力收拾清楚。收拾清楚了，这段能力才算真的能复用。

## 一个标准 Skill 例子

拿一个很常见的能力来举例：`会议纪要整理`。如果把它整理成一个比较标准的 Skill，大概会长这样：

```yaml
name: meeting-summary
goal: 把会议记录整理成一份简洁、可读的纪要

input:
  - 会议逐字稿
  - 参会人名单
  - 会议主题

tools:
  - read_file
  - search_docs
  - write_file

instructions:
  - 先通读会议记录，识别会议主题和关键讨论点
  - 提取明确结论、待确认事项和后续动作
  - 如果出现不清楚的缩写或项目名，先查资料再写
  - 删除重复表达和无关闲聊
  - 结果按“背景 / 结论 / 待办”输出

output:
  format: markdown
  sections:
    - 背景
    - 关键结论
    - 待办事项
    - 风险与未决问题
```

这个例子里，真正重要的不是写法长什么样，而是它已经把一段能力讲清楚了：这段 Skill 解决什么问题，要吃什么输入，可以调用哪些工具，做事时按什么思路走，最后产物长什么样。

也就是说，一个“标准 Skill 结构”不一定非得长成某个固定格式，但通常都应该回答这几个问题：

- 这段能力到底是干什么的
- 它要拿到什么输入
- 它能调用哪些工具
- 它会按什么步骤处理
- 它最后输出成什么样

## Skill 不是工具

这里也很容易混。Skill 不是浏览器，不是数据库，不是搜索接口，也不是文件系统。那些东西是工具。

Skill 更像“怎么使用这些工具去完成一类任务”的整理结果。工具负责干活，Skill 负责把这段活的做法固定下来。

可以这样对照着记：

- LLM：负责理解和生成
- Agent：负责围绕目标去做事
- MCP：负责把外部工具统一接进来
- Skill：负责把一类任务的方法整理成可复用能力

## 为什么有了 Skill，系统会稳定很多

没有 Skill 的时候，很多事情都靠临场发挥。今天让模型这样写，明天换个说法又那样写，结果容易飘，团队里的人也很难复用彼此的经验。

有了 Skill 之后，常见任务就能慢慢沉淀下来。比如“整理长文”“生成摘要”“检查页面文案”“读取一个项目再给修改建议”，这些都可以逐渐变成稳定能力。这样系统做事不会每次都从头开始。

## 用一个内容整理任务来看

假设现在要处理一批杂乱资料：文档、网页、会议记录、截图说明，最后整理成一份简洁摘要。

如果没有 Skill，系统每次都得临时理解这件事：先读什么、怎么取重点、哪些信息要略过、结果要写成什么样。换一批资料，很可能又得重新讲一遍。

如果把这件事整理成一个 Skill，情况就不一样了。输入是什么、优先读哪些内容、怎么归纳结构、要不要调用搜索、最后输出成什么格式，都可以提前写清楚。这样下次再来类似任务，整段能力就能直接复用。

## 为什么这一章要先懂

后面真正开始做 Agent 时，光有模型和工具还不够。系统会慢慢出现另一层东西：哪些能力已经稳定了，哪些只是临时试一下，哪些值得沉淀成以后反复使用的模块。Skill 讨论的就是这件事。

先把位置放正就够了：**Skill 不是一个神秘名词，它只是把一段常用能力整理好、打包好，方便反复使用。**
