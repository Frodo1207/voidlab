## 先跑一遍的价值

这个项目不适合一开始就埋头看代码。先跑起来看一遍，才知道后面那些数据模型、多 Agent、MCP、前端页面到底是在服务什么。

按 `voidagent` 这一章的说明，最小运行环境大致是这些：

- Python 3.10+
- Node.js 16+
- npm 8+
- 至少一套可用的 LLM API
- 地图和图片相关的外部服务 Key

## 要准备哪些 Key

这类项目真正麻烦的，不是把 `npm install` 跑通，而是外部能力没准备好。这个旅行助手至少会碰到几类外部能力：

- LLM：负责整体规划和文本生成
- 地图服务：负责地点搜索、路线、地理信息
- 图片服务：负责结果页里的视觉补充

这些值通常会放进 `.env` 里统一管理。这样前端和后端都知道该从哪拿配置，也方便以后换服务。

## 启动顺序怎么走

这个项目是典型的前后端分离结构，所以最顺的启动方式是：

![旅行助手最短启动链路](../../assets/agent-cookbook/travel-quickstart-flow.svg)

1. 先启动后端，看接口和文档能不能打开
2. 再启动前端，看页面能不能加载
3. 最后从首页填一遍表单，完整走一次规划流程

后端能打开只说明服务活着，前端能打开只说明页面活着，真正算跑通，是从表单提交到结果返回这一整条链路都顺了。

## 跑通之后应该看到什么

如果一切正常，体验会是这样：

- 首页先填目的地、日期、预算、偏好这些信息
- 点击开始之后，会出现加载过程
- 结果页会展示行程概览、预算、景点、地图和天气
- 如果支持编辑和导出，说明项目已经不只是“生成一段文本”

这里最重要的不是界面有多漂亮，而是先确认这个项目的输入、处理中间态、输出三件事都真的存在。
