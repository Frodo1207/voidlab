大多数“内容增长”失败，不是因为你不努力，而是因为你在做单次产出：写完一篇就结束，发完一个视频就结束，数据差了就归因“平台不行”，数据好了也不知道为什么好。

增长闭环的本质是把内容当成系统：**输入→产出→分发→反馈→复盘→更新输入**。你不是在“多发”，而是在持续训练一套可复用的内容机器。

## 一句话结论

增长闭环的唯一目标是：**让每一次发布都能反过来改进下一次发布**。只要你能稳定回收反馈并写入规则库，你就会越做越省力、越做越准。

## 适用对象

- 你在做自媒体/品牌内容/增长，但产出很随机、复盘很主观
- 你想把“数据反馈”变成下一次选题与写作的输入，而不是看完就忘
- 你想让 WorkBuddy 帮你做重复的结构化工作（整理反馈、抽规律、写模板）

## 前置条件

### 1) 先选一个平台作为主战场

不同平台的反馈信号不同。第一阶段不要多平台同时做闭环，选一个主战场：

- 小红书：收藏/评论质量/笔记完读率（间接）
- 抖音/视频号：完播/停留/互动
- 公众号：打开率/读完率/转发

### 2) 给增长闭环一个稳定工作区

增长闭环是典型的“长期系统”，必须把产物与反馈落盘，否则你会永远停留在感觉层面。

```txt
growth/
  input/
    ideas.md                # 选题池（原始输入）
    audience.md             # 目标受众与痛点画像
    competitors.md          # 对标与拆解（可选）
  output/
    2026-08-05_post.md       # 当次产出（脚本/图文/视频文案）
    2026-08-05_pack.md       # 当次发布包（标题/封面/发布文案/评论区引导）
  feedback/
    2026-08-05_metrics.md    # 数据快照（手填或导出）
    2026-08-05_comments.md   # 评论摘录与标签
  system/
    hooks.md                # 开头库（可复用）
    templates.md            # 结构模板库
    dos-and-donts.md        # 经验规则（从反馈抽出来）
    hypotheses.md           # 假设清单（可证伪）
    log.md                  # 复盘回填（每次更新）
```

## 最短路径（可验收）

第一次跑闭环，不要追求“爆”。只要跑通 1 次完整回路就算成功：

1. 从 `ideas.md` 选 1 个选题 → 产出 → 发布
1. 24h 后采集数据与评论 → 写入 `feedback/`
1. 从反馈里抽 3 条规律 → 写入 `system/dos-and-donts.md`
1. 用这 3 条规律改写下一篇的结构或开头

验收标准：

- 每次发布都有 `metrics + comments + log` 三件套落盘
- `dos-and-donts.md` 至少新增 3 条可执行规则（不是感受）

## 闭环最少包含什么

- 选题来源
- 生产模板
- 发布节奏
- 反馈回收
- 复盘迭代

上面这 5 项少一个都不叫闭环。尤其是“反馈回收”和“复盘迭代”，它们决定了系统会不会变强。

## 这类任务最适合 AI 做什么

稳定结构、加快重复部分、帮助你把反馈重新喂回系统。

更具体一点，AI 最适合做三件重复但高价值的事：

- 把评论/私信/数据整理成结构化表（从“噪音”里抽信号）
- 把复盘写成可复用规则（dos/don’ts、模板、hook 库）
- 把规则反向应用到下一次产出（按同一口径改写）

## 关键步骤拆解

### 步骤 1：选题输入要有“来源标签”

选题池不要只有一句话标题，要写清楚来源：

- 来源：用户问题 / 评论区 / 私信 / 竞品爆款 / 你自己的失败经验
- 目标受众：写给谁
- 预期收益：看完能得到什么

这样你后续复盘才能判断：哪类来源更可靠。

### 步骤 2：把生产模板写死（减少随机性）

最推荐的做法是：一开始只允许自己用 1~2 种内容结构。比如：

- 结构 A：反常识开头 → 3 点拆解 → 例子 → 行动建议
- 结构 B：问题开头 → 误区 → 正解流程 → Checklist

模板越少，反馈越可比较。

### 步骤 3：把“发布包”当成交付物

发布包至少包含：

- 标题 10 个备选（含关键词）
- 封面文案 3 套
- 发布文案（含评论区引导）
- 置顶评论（提前写好）

没有发布包，你的内容只是“半成品”。

### 步骤 4：把反馈回收变成固定动作

反馈回收不要靠记忆。建议固定为 24h、72h 两次采集：

- 24h：看“初始分发是否成立”（开头/标题是否能留人）
- 72h：看“长期价值是否成立”（收藏/转发/高质量评论）

### 步骤 5：复盘只回答三个问题

每次复盘别写流水账，只回答三个问题：

1. 哪个环节最影响结果（选题/开头/结构/发布/互动）
2. 证据是什么（数据/评论引用）
3. 下一次我改哪一条规则（写进 dos-and-donts）

### 模板 B：WorkBuddy 任务说明（可直接复制）

```txt
目标：基于 input/ideas.md 产出一篇内容并生成发布包，然后把反馈整理成可复用规则，更新 system/，形成闭环。

输入：
- input/ideas.md（选题池）
- input/audience.md（受众画像）
- system/templates.md（现有结构模板）
- system/hooks.md（现有开头库）

动作：
1) 从 ideas.md 选 1 个选题，先写“一句话价值主张 + 目标受众 + 预期收益”
2) 产出 output/{date}_post.md（按固定模板）
3) 产出 output/{date}_pack.md（标题/封面/发布文案/置顶评论）
4) 我提供 metrics/comments 后：整理 feedback/{date}_metrics.md 与 feedback/{date}_comments.md
5) 抽取 <=3 条可执行规律，更新 system/dos-and-donts.md 与 system/hooks.md 或 system/templates.md

约束：
- 不要写复盘流水账；复盘只产出“证据 + 规则更新 + 下一次实验”
- 规则必须可执行（能指导下一次改写），不要写感受词

输出：
- output/{date}_post.md
- output/{date}_pack.md
- system/log.md（追加本次复盘）
- system/dos-and-donts.md（如有更新）

验收：
- 每次发布都有对应的 metrics/comments/log 落盘
- dos-and-donts 至少新增 3 条可执行规则（或明确写“本次无新增，原因是…”）
```

## 常见坑与排查

- 复盘全是感觉：强制引用数据与评论原句作为证据
- 每次结构都换：先固定 1~2 种模板，否则不可比较
- 只盯点赞不盯信号：根据目标选指标（增长看分发、变现看转化、品牌看高质量评论）
- 不更新系统文件：没有 `system/` 的更新，就不算闭环，只算写作
