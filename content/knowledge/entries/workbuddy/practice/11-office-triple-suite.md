这一篇的目标很直接：把最常见的办公三件套（Word / Excel / PPT）变成**可复用的“交付标准”**。你后面做任何办公任务，都可以用同一套结构去下指令、验收、返工、复盘。

它和“第一个可验收任务”那篇的关系是：那篇教你跑通一次闭环；这一篇把闭环里最常见的三类交付物，拆成可以直接复制的模板与验收规则。[$TRAE_REF](https://workbuddy.homes/bluebook/%E7%AC%AC%E4%B8%80%E7%AF%87%20%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8C%EF%BC%9A%E5%85%88%E6%8A%8A%20WorkBuddy%20%E7%94%A8%E8%B5%B7%E6%9D%A5/%E7%AC%AC%204%20%E7%AB%A0%20%E5%BF%AB%E9%80%9F%E5%AE%8C%E6%88%90%E7%AC%AC%E4%B8%80%E4%B8%AA%20WorkBuddy%20%E4%BB%BB%E5%8A%A1/)

## 先把“办公交付”统一成一个模型

不管你要交付的是 Word、Excel 还是 PPT，一份可验收交付物都可以被统一成同一个模型：

- **输入**：你允许它使用哪些材料（文件、链接、摘要、会议记录）
- **输出**：你要它生成哪些文件（格式、文件名、目录）
- **验收**：你用什么规则判断“通过/不通过”
- **追溯**：关键结论来自哪里（至少做到“能回到输入材料”）

WorkBuddy 的右侧结果区会把产物、文件变更、预览入口集中起来，这也是为什么“输出位置 + 文件名 + 改动清单”比“写得更好看”更重要。[$TRAE_REF](https://workbuddy.homes/bluebook/%E7%AC%AC%E4%B8%80%E7%AF%87%20%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8C%EF%BC%9A%E5%85%88%E6%8A%8A%20WorkBuddy%20%E7%94%A8%E8%B5%B7%E6%9D%A5/%E7%AC%AC%203%20%E7%AB%A0%20WorkBuddy%20%E7%9A%84%E4%B8%BB%E7%95%8C%E9%9D%A2%E3%80%81%E4%BB%BB%E5%8A%A1%E4%B8%8E%E5%B7%A5%E4%BD%9C%E5%8C%BA/)

## 一个通用的目录约定

只要你做的是“办公交付”，我建议所有案例统一用这个最小目录结构（以后团队协作也不会乱）：

```txt
project/
  input/                 # 原始材料（只读）
  output/                # 交付物落点（只写）
  notes/                 # 过程记录 / 口径说明 / 约束
  provenance.md          # 追溯：结论 → 输入证据（可选但强烈建议）
```

最关键的规则是两条：

- **input/ 不改**：需要清洗就写到 `output/`，不要覆写原始材料
- **output/ 可验收**：交付物只认 `output/`，不把文件散落在根目录或临时目录

## Word（文档类）：先定“结论结构”，再谈文采

### Word 的默认结构（推荐）

只要你没有特别要求，Word 文档我建议直接固定成 5 段结构，几乎适用于所有“说明类/方案类/总结类”任务：

- 一句话结论（给领导看的）
- 背景与目标（给协作者看的）
- 核心方案（含取舍：为什么选 A 不选 B）
- 风险与边界（哪些情况不适用）
- 下一步与负责人（让文档能推动事情）

### Word 的验收规则（你可以直接复用）

- 首段必须是一句话结论（不超过 40 字）
- 文档里每个建议必须能对应一个输入依据（或明确标“待确认”）
- 至少列出 3 条风险或限制条件
- 末尾必须给出“下一步动作 + 截止时间 + 负责人”（不知道负责人就写“待指定”）

### Word 的任务说明模板（可直接复制）

```txt
目标：把 input/ 里的材料整理成一份可对外/可汇报的 Word 文档。

输入：
- 仅使用 input/ 下的文件：{列出文件名}

输出：
- output/report_v1.docx
- output/provenance.md（可选，但建议生成）

约束：
- 不要改写 input/ 原始文件
- 无法从输入确认的内容写“待确认”，不要杜撅

验收：
- 首段一句话结论（<= 40 字）
- 文档结构：结论/背景/方案/风险/下一步
- 列出至少 3 条风险
```

## Excel（表格类）：三句话就能把“口径”钉死

Excel 最容易翻车的地方不是公式，而是“口径不一致”：你脑子里的字段含义和它理解的字段含义不一致，最后数据看起来很完整，但结论全是错的。

所以表格类交付，先把下面三件事写清楚，成功率会直接提升一个数量级：

- **统计口径**：字段定义、时间范围、是否去重、是否包含退款/取消等异常
- **输出指标**：哪些列、哪些汇总（按人/按客户/按渠道/按周/月）
- **校验规则**：总和对不对、缺失值怎么处理、异常值怎么标记

### Excel 的验收规则（推荐）

- 必须输出一张“明细表” + 一张“汇总表”（或等价结构）
- 缺失值处理必须写在表头或备注里（例如“缺失=0 / 缺失=未知 / 缺失行剔除”）
- 至少有 2 条自检规则（例如：汇总=明细合计、去重前后数量差异）

### Excel 的任务说明模板（可直接复制）

```txt
目标：把 input/ 下的数据整理成可复用的 Excel（含明细与汇总）。

输入：
- input/data.csv（或 input/*.xlsx）

输出：
- output/analysis_v1.xlsx

口径：
- 时间范围：{写清楚}
- 去重规则：{按什么字段算重复}
- 缺失值处理：{写清楚}

验收：
- Sheet1=明细；Sheet2=汇总
- 汇总值必须能用公式/透视从明细得到
- 输出 2 条自检：{写清楚}
```

## PPT（汇报类）：先把“故事骨架”定死

PPT 的本质不是“排版工具”，而是“观点序列”。如果你不先把骨架定死，它会用一堆看起来合理的页面把你糊过去，最后你既不好验收，也不好返工。

### PPT 的默认骨架（推荐）

- 现状：我们现在在哪里（用数据或事实）
- 问题：当前最关键的障碍是什么（1-3 条）
- 方案：我们要做什么（动作，不是口号）
- 结果：预期能得到什么（指标/里程碑）
- 下一步：本周要推进的具体动作

### PPT 的验收规则（推荐）

- 总页数 <= 10（除非你明确要长 deck）
- 每页只有一个核心观点（用标题句表达，不要“目录式标题”）
- PPT 中出现的关键数字必须能追溯到输入或表格（用 `provenance.md` 或备注说明）

### PPT 的任务说明模板（可直接复制）

```txt
目标：生成一份 8 分钟汇报 PPT。

输入：
- input/summary.md
- input/data.xlsx

输出：
- output/brief_v1.pptx
- output/provenance.md（列出关键结论与来源）

结构：
- 封面
- 现状（1页）
- 问题（1-2页）
- 方案（2-3页）
- 结果/里程碑（1-2页）
- 下一步（1页）

验收：
- <= 10 页
- 每页一个观点，标题句必须是完整陈述句
- 关键数字可追溯
```

## 一次完整的“办公三件套”交付示例

假设你要做一个“销售周报”的闭环（很典型）：

- Word：`output/sales-weekly-report_v1.docx`（详细说明：背景、进展、风险、行动）
- Excel：`output/leads_v1.xlsx`（线索明细 + 汇总）
- PPT：`output/sales-weekly-brief_v1.pptx`（8 分钟投屏汇报）
- 追溯：`output/provenance.md`（所有关键结论回到邮件/会议记录/表格）

你会发现：只要目录和验收规则一致，后面每周你只需要替换 `input/` 里的原始材料，整个工作流就能复用。

## 常见坑（以及怎么避免）

- 只让它“写一份 PPT”，不写输出位置：结果就是文件散落，验收失败
- 让它“分析一下数据”，不写口径：结果就是“看起来很对的错结论”
- 让它“写得更专业”，不写结构：结果就是返工只能靠玄学

如果你要把这套东西进一步固化，下一步就该进入系统沉淀线：把这些模板收成 Skill（或至少收成可复制的任务说明片段），让团队每次都按同一套标准交付。
