这章只做一件事：让你第一次真正跑通一次“从输入到交付”的闭环。你不需要先把所有功能学完，但你必须先完成一次能验收、能落盘、能复用的交付。

官方第 4 章给了一个很实用的框架：创建任务 → 写清任务说明 → 观察计划与文件变更 → 在结果区预览并验收。[$TRAE_REF](https://workbuddy.homes/bluebook/%E7%AC%AC%E4%B8%80%E7%AF%87%20%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8C%EF%BC%9A%E5%85%88%E6%8A%8A%20WorkBuddy%20%E7%94%A8%E8%B5%B7%E6%9D%A5/%E7%AC%AC%204%20%E7%AB%A0%20%E5%BF%AB%E9%80%9F%E5%AE%8C%E6%88%90%E7%AC%AC%E4%B8%80%E4%B8%AA%20WorkBuddy%20%E4%BB%BB%E5%8A%A1/)

## 什么叫“可验收任务”

可验收任务不是“它看起来写得不错”，而是你能用一套明确标准说清楚：

- 交付物是什么（文件格式、文件名、放在哪里）
- 哪些事实必须来自输入材料（不能编造）
- 合格标准是什么（页数、结构、必须包含哪些要素）
- 不合格时怎么返工（指出哪一页/哪一段、改成什么）

如果你只能说“差点意思”“再好看点”，那它就不是可验收任务。

## 如何写一个任务说明

官方给的“任务说明六要素”非常适合当作固定模板：目标、输入、动作、约束、输出、验收。[$TRAE_REF](https://workbuddy.homes/bluebook/%E7%AC%AC%E4%B8%80%E7%AF%87%20%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8C%EF%BC%9A%E5%85%88%E6%8A%8A%20WorkBuddy%20%E7%94%A8%E8%B5%B7%E6%9D%A5/%E7%AC%AC%204%20%E7%AB%A0%20%E5%BF%AB%E9%80%9F%E5%AE%8C%E6%88%90%E7%AC%AC%E4%B8%80%E4%B8%AA%20WorkBuddy%20%E4%BB%BB%E5%8A%A1/)

| 要素 | 要回答的问题 |
|---|---|
| 目标 | 最终要解决什么问题 |
| 输入 | 使用哪些文件、目录、链接或消息 |
| 动作 | 需要分析、整理、转换还是生成 |
| 约束 | 哪些不能改，采用什么规范 |
| 输出 | 交付什么文件，放到哪里 |
| 验收 | 用什么标准判断合格 |

这张表最重要的一点：**一定要把“输出”和“验收”写成可以检查的东西**。否则你会得到一个“看起来完成了”的产物，但无法判断好坏，更无法返工。

## 入门任务 D：整理邮箱邮件 → 输出销售 PPT

这是一个非常典型的“从输入到交付”任务：输入是碎片化邮件，输出是一份可投屏汇报的销售 PPT。它的价值在于：你能同时练到三件事：

- 输入材料如何收束（邮件很碎，必须先变成可用的事实清单）
- 交付物如何定义（销售 PPT 的结构、页数、受众）
- 验收如何落地（哪些结论能在邮件里找到依据）

### 场景上下文（你要它解决的问题）

假设你是销售/售前，邮箱里有一周的客户往来邮件（询价、问题、反对意见、推进状态）。你需要给销售负责人做一个 8 分钟的简报：

- 本周新增线索、推进中线索、停滞/流失线索
- 客户最常问的问题和反对点（价格/交付/合规/集成）
- 下一步要你或团队做的动作（待回复、待报价、待开会、待确认）

### 任务准备（把输入做成“可被引用的材料”）

你有两种输入方式：

- 连接器方式：如果你已经在 WorkBuddy 里接入邮箱或 IM 助理，让它在你授权范围内读取指定邮件（例如某个标签/某段时间/某些联系人）
- 文件方式：把邮件导出为 `input/emails.md` 或 `input/emails.txt`（按时间顺序），放进工作区目录

第一次建议走文件方式：边界更清晰、更容易验收，也更符合“演练目录先跑通”的原则。[$TRAE_REF](https://workbuddy.homes/bluebook/%E7%AC%AC%E4%B8%80%E7%AF%87%20%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8C%EF%BC%9A%E5%85%88%E6%8A%8A%20WorkBuddy%20%E7%94%A8%E8%B5%B7%E6%9D%A5/%E7%AC%AC%204%20%E7%AB%A0%20%E5%BF%AB%E9%80%9F%E5%AE%8C%E6%88%90%E7%AC%AC%E4%B8%80%E4%B8%AA%20WorkBuddy%20%E4%BB%BB%E5%8A%A1/)

### 任务说明模板（可直接复制）

把下面这段直接粘到 WorkBuddy 的任务输入框里即可：

```txt
目标：把 input/emails.md 里的一周客户邮件整理成一份“销售周报简报 PPT”，用于 8 分钟内部汇报。

输入：
- 仅使用当前工作区的 input/emails.md（不要访问工作区外文件）。
- 邮件可能包含重复转发、引用历史，请去重并保留原始出处。

动作：
1) 先把邮件整理成结构化线索清单（按客户/线索聚合）：当前阶段、关键诉求、关键阻塞、下一步动作、负责人/时间（缺失则标记待确认）。
2) 再基于线索清单生成 PPT（<= 10 页）：封面、总览、线索进展、Top 反对点/问题、需要团队支持、下周计划。

约束：
- 不要杜撰任何客户事实或数字；无法从邮件确认的内容写“待确认”。
- 不要改写原始邮件文件；如需清洗，写到 output/ 派生文件。
- 输出内容不得包含敏感信息（手机号/完整邮箱/详细报价等），必要时打码或用占位符。

输出：
- output/sales-weekly-brief_v1.pptx
- output/leads.xlsx（线索清单）
- output/provenance.md（列出每条关键结论对应的邮件片段/日期，方便我验收）

验收：
- PPT 每页只有一个核心观点，投影可读。
- PPT 中出现的每个关键结论/数字，都能在 provenance.md 里找到邮件依据。
- leads.xlsx 的线索数量和 input/emails.md 中的有效线索一致（去重后）。

开始前先给我一个“计划 + 目录草案（PPT 逐页标题）”，我确认后再生成最终文件。
```

### 你怎么验收（把“通过/不通过”说清楚）

验收时别只看 PPT 漂不漂亮，优先看三件事：

- **落点**：产物是否出现在 `output/`，文件名是否符合预期
- **可追溯**：关键结论能不能回指到邮件（`provenance.md` 是否能对上）
- **可复用**：下周你只要换一个新的 `emails.md`，这个模板还能跑通吗

### 返工怎么说（让它改得可控）

返工指令只要抓住同一条逻辑：定位 → 标准 → 改法 → 再交付。比如：

```txt
第 4 页“Top 反对点”不通过：你把价格异议写成了“预算不足”，但邮件里没有这句话。
请按 provenance.md 回查原文，把该条改为“客户对价格档位不理解（待确认预算）”，并在备注里列出需要我补充确认的问题。
修改后输出 output/sales-weekly-brief_v2.pptx，并给出变更摘要（改了哪几页、改了哪些要点）。
```

## 复盘：把一次成功沉淀下来

当你用上面的模板连续跑通 2~3 次，就可以开始把它沉淀成“你自己的固定工作流”：

- 把任务说明保存为 `templates/sales-email-to-ppt.txt`
- 把验收规则保留（尤其是 `provenance.md` 这类可追溯机制）
- 再考虑把它封装成 Skill，让团队也能用同一套输入方式复现你的结果
