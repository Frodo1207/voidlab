这篇解决一个新手最常见的卡点：你不是不知道 WorkBuddy 能做什么，你是不确定“应该从哪个入口进入”。更稳的做法是：**先按任务语境选“日常办公 / 代码开发 / 设计创意”，再按执行风险选 Ask / Plan / Craft。**

![选择 Ask / Plan / Craft（执行方式）](https://workbuddy.homes/assets/003_image_W7VqbwVeJo.1GRpiN8R.png)

## 它们和 Ask / Plan / Craft 的区别

很多人会把这三个入口当作“功能高低”，或者误以为它们决定“能不能改文件”。其实更接近的理解是：

| 维度 | 你在选择什么 | 解决什么问题 |
|---|---|---|
| 日常办公 / 代码开发 / 设计创意 | 工作语境（任务语气、常见交付物、默认关注点） | 让 WorkBuddy更快理解你要做哪类事 |
| Ask / Plan / Craft | 执行方式（先问答/先规划/直接动手） | 让执行过程更可控或更快 |

你完全可以在“代码开发”语境里先用 Plan，也可以在“日常办公”语境里直接用 Craft；它们是两层选择，不是二选一。

## 日常办公

适合文档、表格、汇报、邮件整理、会议后处理、资料提炼这类任务。重点不是“写得漂亮”，而是**结构清晰、信息可追溯、输出可复用**。

典型输入：

- 邮件、会议纪要、长文资料、表格数据、链接集合

典型交付：

- `md/docx` 的结构化文档
- `xlsx` 的清单与汇总表
- `pptx` 的汇报稿（更偏信息组织）

如果你做的是“销售周报 PPT”这类汇报，通常就是日常办公语境：核心是信息收束与结构，而不是视觉包装。

## 代码开发

适合处理代码库、脚本、接口、命令行、调试与重构这类任务。重点是**可运行、可修改、可验证**。

典型输入：

- 项目目录、报错堆栈、接口文档、配置文件

典型交付：

- 可运行的代码改动（以及改动说明）
- 可复现的调试步骤
- 面向团队的技术说明文档

如果你要的是“修一个 Bug”“搭一个小工具”“把脚本跑通”，就算最终也要写成一页汇报，它的语境仍然属于代码开发。

## 设计创意

适合做封面、海报、视觉稿、版式探索、内容包装这类任务。重点是**风格、版式、表现力**，而不是“信息是否齐全”。

典型输入：

- 品牌调性、参考图、色板/字体、主题与受众

典型交付：

- 封面图、海报、社媒卡片
- PPT 视觉风格稿（更偏排版与气质）
- 一组可复用的版式组件与规范

同样是 PPT，如果你的目标是“给发布会/路演做一套更有气质的视觉表达”，就更偏设计创意。

## 选择原则

不要按“自己是什么岗位”来选，而是按“你要交付什么”来选：

- 你要交付的是**信息汇报、整理、清单、结构化文档**：选日常办公
- 你要交付的是**代码/脚本/可复现的调试结果**：选代码开发
- 你要交付的是**视觉方案、风格、版式与包装**：选设计创意

如果你仍然犹豫，可以用一个更简单的判断题：你这次更怕“信息不全”还是更怕“看起来不够好看”？前者偏日常办公，后者偏设计创意。

## 如果你现在只想先开始

第一次上手，默认建议走这条路：

1. 选择日常办公
2. 用 Plan 先让它把计划和交付清单写出来
3. 你确认后再让它执行生成文件

你一旦跑通一次可验收交付，再回头切换到代码开发或设计创意，会更容易看懂这些入口到底在帮你什么。
