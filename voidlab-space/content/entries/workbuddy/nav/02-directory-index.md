这一页不是“把所有标题列一遍”的目录，而是当前 WorkBuddy Space 的正式导航页。你可以把它当成一张地图：先判断自己现在卡在哪，再决定是先补基础、先看案例，还是直接进入系统化沉淀。

## 先怎么进入

如果你是第一次读，最稳的顺序仍然是：

- 先看 `00-space-intro.md`：理解 WorkBuddy 为什么不是“更会聊天的 AI”，而是任务式工作台
- 再看 `00-install-login.md` + `01-permissions-and-workspace.md`：先把环境和边界设对
- 然后看 `04-ui-and-workflow.md` + `06-first-acceptable-task.md`：把界面理解和第一次交付连起来
- 最后再补 `02-modes-overview.md`、`03-model-and-cost.md`、`05-concept-alignment.md`：把模式、成本和术语心智补完整

如果你不是来系统学习，而是手里已经有任务，就可以直接跳到后面的“按目标进入”。

## 导读与导航

这一组回答的是“这套内容怎么读、从哪里进入、参考了什么”。

- `00-space-intro.md`：Space 导读。适合第一次进入，用来建立“从回答问题到交付结果”的整体心智。
- `01-reading-path.md`：阅读路线。适合不想顺读、只想按当前目标分流进入的人。
- `02-directory-index.md`：目录索引。就是你现在看到的这页，用来总览全局和快速跳转。
- `03-sources-and-citations.md`：资料来源与引用说明。适合想知道哪些内容来自官方蓝皮书、哪些是本地重组改写。
- `99-changelog.md`：更新日志。适合后续追踪这套 Space 的结构性调整。

## 入门

这一组的目标很明确：先把第一次可验收任务跑通，不在第一步引入过多高级能力。

- `00-install-login.md`：安装与登录。解决“从 0 到可用”的最小启动问题。
- `01-permissions-and-workspace.md`：权限模型与工作区。解决“能碰什么、做到哪一步需要确认”的边界问题。
- `02-modes-overview.md`：三种模式怎么选。解决“日常办公 / 代码开发 / 设计创意”该怎么理解。
- `03-model-and-cost.md`：模型与成本控制。解决 Auto / Max 怎么选，以及为什么真正要控制的是任务形状。
- `04-ui-and-workflow.md`：主界面、工作区与任务流。解决“左中右三区域分别负责什么”。
- `05-concept-alignment.md`：核心概念对齐。解决专家、Skill、连接器为什么不是一回事。
- `06-first-acceptable-task.md`：第一个可验收任务。用“整理邮箱邮件并输出销售 PPT”的例子，把输入、执行、交付、追溯串成闭环。

如果你现在只补一篇，我会更建议先看 `06-first-acceptable-task.md`。因为它最能把前面那些抽象概念，压成一次真的任务闭环。

## 实战案例

这一组面向“我已经会基本操作，现在想看具体任务怎么跑”的人。

- `11-office-triple-suite.md`：办公三件套。已具备基础内容，适合作为实战线入口。
- `12-file-organization.md`：文件整理与检索。计划补成“目录治理 + 检索 + 输出清单”的案例。
- `13-remote-continuity.md`：远程与接续。计划补成跨设备、跨会话连续工作的方法。
- `15-info-digest.md`：资讯整合：每日通知。计划补成持续收集与固定输出的案例。
- `16-collection-to-knowledge.md`：收藏到知识。计划补成“收集 → 清洗 → 入库 → 可复用”的链路。
- `17-meeting-followup.md`：会议后处理。计划补成纪要、待办、回传与归档的工作流。
- `18-investment-analysis.md`：投资分析日常化。计划补成研究、比较与日报化输出。
- `19-video-team.md`：一句话召唤视频团队。计划补成多角色协作型内容生产案例。
- `20-growth-loop.md`：增长闭环。计划补成从观察、分析到动作回填的闭环案例。
- `21-geo-expert.md`：GEO 实战。计划补成地域化 / 本地化专家任务示例。

这一组目前已经有目录骨架，但除了 `11-office-triple-suite.md` 以外，更多还是待展开状态。

## 系统沉淀

这一组不是教你“先用起来”，而是教你“把一次成功收成可复用系统”。

- `22-skill-distillation.md`：Skill 设计。已具备基础内容，适合作为系统线入口。
- `23-template-library.md`：模板库。计划补成交付模板、提示模板、目录模板的统一管理方式。
- `24-connector-strategy.md`：连接器策略与授权边界。计划补成“什么时候接、接多大、风险怎么控”。
- `25-automation-reliability.md`：自动化可靠性。计划补成定时任务、失败恢复与可追溯机制。
- `26-multi-agent-design.md`：多 Agent 系统设计。计划补成角色分工、协作边界与汇总机制。
- `27-team-rollout.md`：团队落地。计划补成权限、模板、流程和培训的组织化部署方法。

如果你已经跑通过几次任务，下一步最值得看的通常不是“再学一个新功能”，而是开始看 `22-skill-distillation.md`，把一次成功变成以后都能复用的方法。

## 当前进度怎么看

到现在为止，这套 Space 已经基本把“导读 + 入门主干”搭出来了，尤其是安装、权限、模式、模型、主界面、第一个任务和概念对齐，已经不再是空骨架，而是能直接阅读的教程页。当前更明显的空缺在两块：

- 实战案例线还需要逐篇补成完整案例
- 系统沉淀线除了 Skill 设计，还需要继续把模板、连接器、自动化和多 Agent 展开

所以最适合把这页当作一个判断器：你现在是要“先用起来”，还是“把已经跑通的东西沉淀下来”。
