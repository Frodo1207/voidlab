这篇要解决的是一个很“反直觉”的事实：**收藏越多，你越不可能再用**。因为收藏默认没有结构、没有检索口径、没有提炼结论，最后会变成一个只增不减的“信息墓地”。

WorkBuddy 真正适合介入的地方，是把“收藏”改造成一个**可持续复用的知识流**：收集 → 归类 → 提炼 → 入库 → 可再次调用。

## 一句话结论

一条收藏只有在满足下面三件事时，才算“进了知识库”：

- 有主题与标签：你知道它属于哪个问题域
- 有可复用结论：不是原文搬运，而是你以后能直接引用的观点/规则/流程
- 有稳定落点：进入一个你会持续检索的结构（而不是散落在 App 里）

## 为什么单纯收藏没有用

因为你下次找不到、想不起、也不会再打开。更准确地说，“收藏无用”通常有三类原因：

- **不可检索**：你记不住关键词，也没有统一命名/标签
- **不可复用**：收藏的是原文，不是“你要用的结论”
- **不可接续**：没有下一步动作，它只是一条静态链接

## 适用对象

- 你有大量收藏（文章/视频/截图/网页/代码片段），但回头率极低
- 你希望把收藏变成可调用的“素材库/方法库/案例库”
- 你希望每天的输入最终能沉淀到知识库，而不是只当日消费

## 前置条件

### 1) 先给收藏一个“收件箱工作区”

和文件整理一样，你需要一个明确边界，否则你会不断把内容丢进不同 App，然后再也收不回来。

推荐目录结构（最小可用）：

```txt
collection/
  inbox/                 # 原始收藏（只进不出）
  notes/                 # 你的提炼稿（可编辑）
  entries/               # 最终知识条目（可发布/可引用）
  output/
    manifest.csv         # 索引清单：可检索、可审计
  rules/
    topics.md            # 主题清单（<= 7）
    rubric.md            # 提炼与验收口径
```

### 2) 主题清单必须是“有限集”

主题超过 7 个，你的系统就会退化为“想到啥写啥”。建议用你每天真的会用的主题来定义，例如：

- `产品策略`
- `内容增长`
- `销售与运营`
- `工程效率`
- `AI/模型`

## 最短路径（可验收）

第一次不要试图把历史全部收藏都清掉。最短可验收路径是：**挑 10 条收藏做一次完整的入库**。

你要拿到 3 个交付物：

- `entries/` 下新增 3~5 条“可发布条目”（每条带结论与可复用模板）
- `output/manifest.csv`：至少包含 10 条收藏的索引与状态
- `rules/topics.md` 与 `rules/rubric.md`：主题与提炼口径被写死

## 关键步骤拆解

### 步骤 1：把收藏统一收进 `inbox/`（先别急着提炼）

你可以用两种方式输入：

- 文件方式：把网页/文章导出为 `md/pdf`，截图放 `png`，视频链接写成 `md`
- 连接器方式：如果你已经接入浏览器/阅读器/笔记工具，通过连接器抓取内容

无论哪种方式，都建议最终落到工作区目录里。WorkBuddy 最稳定的工作方式仍然是：在一个明确工作区里读写文件、生成产物，然后在结果区验收。[$TRAE_REF](https://workbuddy.homes/bluebook/%E7%AC%AC%E4%B8%80%E7%AF%87%20%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8C%EF%BC%9A%E5%85%88%E6%8A%8A%20WorkBuddy%20%E7%94%A8%E8%B5%B7%E6%9D%A5/%E7%AC%AC%203%20%E7%AB%A0%20WorkBuddy%20%E7%9A%84%E4%B8%BB%E7%95%8C%E9%9D%A2%E3%80%81%E4%BB%BB%E5%8A%A1%E4%B8%8E%E5%B7%A5%E4%BD%9C%E5%8C%BA/)

### 步骤 2：把“提炼口径”写成模板（避免它自由发挥）

收藏入库最怕的就是“AI 写一篇读后感”。你真正需要的是结构化提炼。

推荐口径（够用且可验收）：

- 主题：它属于哪个主题（必须从 `topics.md` 里选）
- 结论：一句话（<= 40 字）
- 证据：原文里支撑结论的关键段落/数据（带引用/链接）
- 方法：如果这是一个方法论，写成 3~7 步的流程
- 适用/不适用：边界条件
- 可复用模板：给出一个可复制的提示词/清单/目录骨架

### 步骤 3：把“索引清单”当成主入口，而不是让内容散落

你最终会有很多条目；真正能帮你找回的不是记忆，而是索引。

`output/manifest.csv` 推荐至少包含：

| 列 | 含义 |
|---|---|
| id | 唯一编号（日期+序号即可） |
| title | 收藏标题（或你给的标题） |
| topic | 主题（来自 topics.md） |
| status | inbox / drafted / published |
| source | 原始链接或来源 |
| entry_path | 对应条目的路径（entries/xxx.md） |

### 步骤 4：把条目写成“能再次调用”的形状

一条知识条目如果只是摘要，它仍然不够。你要让它变成“下一次任务能直接调用的东西”，比如：

- 一份检查清单
- 一段可复制的任务说明（目标/输入/约束/输出/验收）
- 一个目录结构骨架
- 一个可以交给团队复用的 SOP

这也是为什么“可复用模板”是必填字段。

## 可复用模板

### 模板 A：单条收藏的提炼卡片（notes/）

```md
# {标题}

## 主题
- {从 topics.md 里选一个}

## 一句话结论（<= 40 字）
- 

## 证据（引用原文）
- 引用：
- 来源：

## 方法 / 流程（如果有）
1.
2.
3.

## 边界（适用 / 不适用）
- 适用：
- 不适用：

## 可复用模板
- （把它写成你下次能直接复制粘贴的片段：提示词/清单/目录骨架）
```

### 模板 B：WorkBuddy 任务说明（可直接复制）

这段仍然遵循“目标/输入/动作/约束/输出/验收”的可验收写法。[$TRAE_REF](https://workbuddy.homes/bluebook/%E7%AC%AC%E4%B8%80%E7%AF%87%20%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8C%EF%BC%9A%E5%85%88%E6%8A%8A%20WorkBuddy%20%E7%94%A8%E8%B5%B7%E6%9D%A5/%E7%AC%AC%204%20%E7%AB%A0%20%E5%BF%AB%E9%80%9F%E5%AE%8C%E6%88%90%E7%AC%AC%E4%B8%80%E4%B8%AA%20WorkBuddy%20%E4%BB%BB%E5%8A%A1/)

```txt
目标：把 collection/inbox/ 下的收藏整理成可复用知识条目，并写入 entries/，同时输出可检索的 manifest.csv。

输入：
- collection/rules/topics.md
- collection/rules/rubric.md
- collection/inbox/ 下的 10 条收藏（文件或链接列表）

动作：
1) 为每条收藏选定 topic（必须来自 topics.md）
2) 按 rubric 提炼成 notes/ 草稿（结论/证据/方法/边界/可复用模板）
3) 将高价值的 3~5 条整理成 entries/ 条目（可发布形态）
4) 输出 output/manifest.csv，记录每条收藏的状态与 entry_path

约束：
- 不要写读后感；每条必须输出“一句话结论 + 可复用模板”
- 无法判断主题或价值的内容，标记为 pending-review，不要硬编
- entries/ 只收“能再次用起来”的条目；其余停留在 notes/ 或 inbox/

输出：
- collection/entries/*.md（3~5 条）
- collection/output/manifest.csv（>=10 条）
- collection/rules/rubric.md（如有必要，补充规则变化）

验收：
- 我随便抽一条 entries/，都能直接复制里面的模板去完成一个任务
- manifest.csv 能让我按 topic 检索到条目路径
```

## 常见坑与排查

- 你越做越像在写百科：说明你在“总结”，而不是在“提炼可复用模板”。强制每条输出一个模板。
- 主题越分越细：说明主题清单没有限制。把 topics.md 固定为有限集，不在任务中增主题。
- 条目越来越多但越来越难找：说明你缺少 `manifest.csv` 或没有稳定命名/索引口径。
- 只存原文不写证据：看似省事，但以后无法追溯。至少给每条重点附一个来源链接。

## 判断标准

一条收藏是否有价值，取决于你下次能不能把它再调出来用。更具体一点：

- 你能不能在 30 秒内按主题找到它（索引有效）
- 你能不能在 2 分钟内复用它里面的模板完成一个任务（模板有效）
- 你能不能说清楚它不适用于什么情况（边界有效）
